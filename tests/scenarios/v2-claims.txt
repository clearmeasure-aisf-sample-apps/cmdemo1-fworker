# The suites and scenarios that v2 claims: the matrix jobs "Tier 1 (v2 ...)" of .github/workflows/tests.yml run each line below with
# `run-all.ps1 -Engine v2` (run.ps1 -Engine v2 -Tier full: FACTORY_ENVIRONMENT v2ci, or the suite's own name where it sets one (tdd for copilot, promote, envscope), engine.v2Environments naming it,
# FACTORY_DB_CONNECTION a SQL Server of its own), after the same line has run on the v1 engine in the Tier 1 shards. A claim is the proof that the engine produces what v1 produces: the checks and the
# golden writes of the scenario are the oracle for both (tests/scenarios/golden; where v2 writes differently on purpose, the difference is declared in golden/v2-differences.txt).
#
# One claim per line:
#   <suite>                                       every scenario of the suite (a whole-suite claim; the suite is then claimed by this line alone)
#   <suite> | <regex>                             the scenarios of the suite whose name matches the regular expression (run.ps1 -Suite <suite> -Only <regex>)
#   <suite> [| <regex>] | profile=<name>          the test profile of the gateway (run.ps1 -V2Profile): plain (the default), saga-docs or saga-feature, which turn the engine's intake on so that the Todo
#                                                 items of the suite start a WorkItemSaga (the suite 'saga')
#   v1-only <suite> | <reason>                    a suite that stays on v1, with the reason: it is neither claimed nor missing
# A line that starts with # and a blank line are comments. A claim must name a suite of `run.ps1 -ListSuites` and match at least one scenario of it: the run fails on a claim that lists none, so a renamed
# suite or scenario cannot leave a claim empty. tests/ci/run-v2-claims.py checks this file and the matrix of tests.yml (every claimed suite in exactly one v2 job; the coverage job runs it).
#
# The precondition of W9.9c is that the claim list equals `run.ps1 -ListSuites` less the declared v1-only suites, every suite claimed whole: `run-v2-claims.py ... --require-complete`, which the job
# "Every scenario is in exactly one shard" runs, so the list stays complete: a suite appended to run.ps1 is claimed whole or declared v1-only in the same pull request. A suite claimed by scenarios is not claimed whole.

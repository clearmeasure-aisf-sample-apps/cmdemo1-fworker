# The text of the prompts the Cursor and Copilot runtimes put together (Templates/RuntimePrompts.cs says when each section is used).
# Format: a line "@@ <name>" starts a section; its text is the lines up to the next "@@" line, each with its newline, so an empty first line is
# a leading newline. {name} is a placeholder, filled in one pass (a value is never read for placeholders). Lines before the first section are
# comments. Every byte counts: tests/Gateway.Tests/Pins/runtime-prompts.json pins the rendered prompts.
@@ copilot-followup-first
FIRST, before you read or change anything: call fworker_connect with code {code} and gateway {gatewayUrl}, then next_event (wait_seconds 30) until item.assigned for #{item} arrives, then item_accept for #{item}. Without that the gateway cannot see this session: its work is not recorded and the session counts as failed. Only then do the step below.
@@ copilot-followup-head
Follow-up session of the task that owns #{item}: phase {phase}. Work on PR #{pr}, branch {branch} (this session runs on it). If `git branch --show-current` shows a different, newer copilot/ branch of this same task, that branch is the item's pull request now (Development: call pr_open with it as head; other phases: work on it); never report FAILURE for that. You own #{item} until it is merged and master is green, but THIS session does only this phase step and then ends: never poll or wait for CI; the gateway watches it and resumes you.
@@ what-changed
What changed: {why}
@@ copilot-followup-development
Fix it on this branch. Before the push run the private build (pwsh ./PrivateBuild.ps1) and the acceptance tests (pwsh ./AcceptanceTests.ps1); push (plain push) only when both pass (a failing test outside your change that also fails at origin/master, or a full acceptance run that fails only outside your change's area or does not finish in 20 min while the private build and the acceptance tests of your area pass, does not block: push and name it in item_complete), else fix and rerun. Push as soon as the gate allows. Then pr_open with head {branch}, item_complete with both results, session_end.
@@ copilot-followup-functional-testing
Verify PR #{pr} against the item's criteria; change nothing; record the review and the verdict, then session_end.
@@ copilot-followup-other
Do this phase's step only, then session_end.
@@ copilot-pr-development

This item's pull request: #{pr}, branch {branch}. This task starts from that branch; Copilot gives the task its own branch made from it. Fix #{pr}: read why once (pr_checks for the failed job's log, item_get for the review), change the code on the branch this task runs on, which already holds #{pr}'s commits, push, and pass THAT branch as `head` to pr_open, then item_complete and session_end. The gateway makes your task's pull request the item's, closes #{pr} as superseded and waits for the checks itself. Do not start over from master and open nothing else. If the branch you run on is a newer branch of this same task than #{pr}'s, it is the item's pull request: call pr_open with it as head, do not fail.
@@ copilot-pr-other

This item's pull request: #{pr}, branch {branch}. This task starts from that branch; Copilot gives the task its own branch made from it. Verify #{pr}; change nothing.
@@ copilot-connect

This session's work item: #{item}, phase {slug} (column {phase}).
Your gateway URL for fworker_connect: {gatewayUrl}
Your one-time code for fworker_connect: {code}
@@ cursor-followup
Follow-up run: you still own #{item}. Its next phase is {phase}. The fworker MCP server has a fresh credential for this run: call next_event until item.assigned for #{item} arrives, then item_accept, before anything else. Do only this phase, then session_end; never poll or wait for CI: the gateway watches it and starts your next run.
@@ cursor-followup-development
Fix it on factory-worker/{item}-development (fetch it first: git fetch origin; git checkout factory-worker/{item}-development; git pull). Run the private build and the acceptance tests before the push, as the rules below say; then pr_open with that branch, item_complete, session_end.
@@ cursor-work-item

This session's work item: #{item}, phase {slug} (column {phase}).
